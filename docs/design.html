1. Purpose

Northline agents today are the integration layer: they take facts from the caller, look up the policy, find a garage, and narrate next steps while the member waits. Assist automates those four boxes. A human specialist still owns denials and any override. The product does not dispatch a truck.

2. As-is workflow

Figure 1. Every box is a person with a headset. Time is spent in all four; errors concentrate in coverage and garage selection.

3. Target workflow

Figure 2. SMS is always drafted, never auto-sent. Approve sends the coverage text; Decline sends the hold text. A specialist must close every case.

5. How voice becomes text

Flask never receives audio. The laptop microphone is handled entirely in Chrome. Gemini only ever sees a text string, the same as if the member had typed.

sequenceDiagram
  autonumber
  actor Member
  participant Chrome as Chrome browser
  participant STT as Web Speech API
  participant UI as voice.js
  participant API as Flask POST /utterance
  participant LLM as Gemini Flash

  Member->>Chrome: click mic and speak
  Chrome->>STT: audio from the microphone
  Note over STT: Built into Chrome. Not our server. Not Gemini.
  STT-->>Chrome: plain text e.g. I have a flat tire
  Chrome->>UI: onresult transcript
  UI->>API: JSON { text: "I have a flat tire" }
  API->>LLM: extract facts from that text
  LLM-->>API: name, vehicle, location, issue, listed driver
  API-->>UI: next question
  opt Speak replies checked
    UI->>Chrome: speechSynthesis.speak
    Chrome-->>Member: spoken reply
  end

Figure 3. Speech-to-text is Chrome’s Web Speech API. The type box is the same path with the STT step skipped. Use Chrome; Firefox/Safari often have no usable SpeechRecognition.

Extracted facts (jargon: “slots”) are the structured fields we fill from that text: caller name, vehicle, location, issue type, listed driver, short situation. The transcript is the raw sentences. The fact panel is the form those sentences get turned into so coverage can run without re-reading the chat.

6.2 What happens inside Flask

Routes only parse HTTP and call CaseService. That class is the only place status may change. Four collaborators each do one job.

flowchart LR
  Routes[web and api routes] --> CaseSvc[CaseService]
  CaseSvc --> Conv[Conversation]
  CaseSvc --> Cov[Coverage]
  CaseSvc --> Dsp[Dispatch]
  CaseSvc --> Nfy[Notify]
  Conv -->|JSON next question plus facts| Gemini[Gemini Flash]
  Cov -->|JSON coverage after rules| Gemini
  Cov --> Policy[policy markdown]
  Dsp --> Garages[garages.csv]
  Nfy --> SmsFile[sms.csv]
  CaseSvc --> Cases[cases.csv]

Figure 5. Dispatch and Notify never call Gemini. Conversation and Coverage do.

7. Sequence diagrams

The specialist console is omitted from the arrows below. For the whole case it runs GET /api/cases/{id} every second and reads the last CSV write. It is not in the member’s call stack.

7.1 Intake — every case, status stays gathering

Repeats until Finish call — run coverage. If there is no Gemini key, Conversation still returns extracted facts and a next question; the rest of the product is unchanged.

sequenceDiagram
  autonumber
  actor Member
  participant UI as Customer UI
  participant API as CaseService
  participant Talk as Conversation
  participant LLM as Gemini Flash
  participant DB as cases.csv

  Member->>UI: Start call
  UI->>API: POST /api/cases
  API->>DB: insert gathering
  API-->>UI: greeting

  loop until Finish call
    Member->>UI: speak or type
    UI->>API: POST /utterance
    API->>Talk: reply(case, text)
    alt GEMINI_API_KEY set
      Talk->>LLM: transcript to JSON
      LLM-->>Talk: next question plus facts
    else offline
      Talk-->>Talk: keyword facts
    end
    Talk-->>API: assistant_message and facts
    API->>DB: save, still gathering
    API-->>UI: speak reply
  end

Figure 6. Intake does not run coverage, garage, or SMS. Specialist buttons stay locked.

Figure 7. Covered: garage is chosen, SMS is drafted, then Approve sends it and closes. Decline is still available if the specialist disagrees.

7.3 Not covered or needs review — unlisted driver, lapsed, unknown caller

Examples: Maya with “my brother is driving”; Derek lapsed; Start without a member. Dispatch is skipped. SMS is drafted and not sent. Same as 7.2 until coverage returns not_covered.

sequenceDiagram
  autonumber
  actor Member
  participant UI as Customer UI
  participant API as CaseService
  participant Cov as Coverage
  participant Dsp as Dispatch
  participant Nfy as Notify
  participant DB as cases.csv
  actor Spec as Specialist

  Member->>UI: Finish call
  UI->>API: POST /assess
  API->>Cov: assess(case)
  Cov->>Cov: hard rule
  Note over Cov: unlisted or lapsed = not_covered. No member = needs_review.
  Cov-->>API: not_covered or needs_review
  API--xDsp: skip garage
  API->>Nfy: draft SMS only
  Note over Nfy: sms_sent stays no
  API->>DB: awaiting_human, action none
  alt confirm denial
    Spec->>API: POST /decline
    API->>Nfy: send held SMS
    API->>DB: closed_declined
  else change the decision
    Spec->>API: POST /override
    Note over API: Figure 9. Does not close.
  end

Figure 8. Approve is disabled until the decision is covered. The model never closes this path.

7.4 Override — rewrite the decision, still do not close

sequenceDiagram
  autonumber
  actor Spec as Specialist
  participant API as CaseService
  participant Dsp as Dispatch
  participant Nfy as Notify
  participant DB as cases.csv

  Note over Spec,DB: Only while awaiting_human. Note is required. No Gemini call.
  Spec->>API: POST /override decision plus note
  alt decision covered
    API->>Dsp: recommend(case)
    Dsp-->>API: garage
    API->>Nfy: redraft SMS
  else not_covered or needs_review
    API->>Nfy: redraft hold SMS
    Note over API: garage cleared
  end

  Spec->>API: POST /approve or /decline
  API->>DB: closed_covered or closed_declined

Figure 9. Override is a specialist write. Closing is a second click.

8. Where the LLM is used

Tow vs mobile + garageNoRule table + haversine over garages.csv.

9. Human-in-the-loop

  • Every case: SMS is drafted and held. Approve sends the coverage text (covered only). Decline sends the hold/denial text.
  • not_covered / needs_review: Approve is disabled until a specialist overrides to covered.
  • Override redrafts SMS, sets sms_sent=no, and does not close.
  • Writes go through the Flask API, not through the model.

10. Out of scope for v1

Telephony / IVR, photo damage models, dispatch write-back, taxi and rental booking, authentication, and multilingual support.
